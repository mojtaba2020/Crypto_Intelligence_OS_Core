## A. The one command to use most often

**Send exactly:** `قله: ادامه`

On that command ChatGPT must, **during its current answer**:

1. Fetch this command center, the canonical North Star, AGENTS.md and the latest relevant PR/issue/workflow artifacts through the connected GitHub app. If access fails, disclose it rather than substitute guesses.
2. Derive the **currently authorized stage/gate** from source evidence, not from static chat memory. The Phase-5/Stage-6 baseline stands unless independently grounded acceptance evidence supports a change.
3. Choose **one highest-value, unblocked, measurable action on the critical path**; work on an isolated branch/PR and invoke available tools now. Maintain the parallel **Track A price/history** and **Track B fundamentals/macro/on-chain/news**. Do not let a narrow BTC4h or tooling defect consume more than one bounded diagnostic pass without returning to E2/E3.
4. Check the actual tests/CI/logs when runnable; if no CI has finished, state its true status. If code changes are not justified, produce a real auditable artifact such as a GitHub review or source coverage manifest—not a superficial progress message.
5. Update the relevant PR/issue/checkpoint with work performed, evidence links, blockers, and **next exact step**. Do not write to protected experimental results.
6. Report briefly in Persian using the standard status format in section C.

**Important:** The command authorizes an attempt **in the chat turn**, not 24/7 background execution, automatic Codex access, unrestricted spending, trades, model promotion or deployment.

## A.1. Mandatory four-channel operator cycle (founder directive 2026-11-21)

**Every `قله: ادامه` must inspect and report four execution channels: ChatGPT, Codex, task-specific agents, and GitHub.** It must attempt real permitted delegation when a connected executor exists; naming a role, describing a prompt, or passing CI must never be reported as an agent or Codex execution.

1. **ChatGPT / Orchestrator — always active in this turn:** inspect the current GitHub mission, independent gate evidence, recent PR/issue/CI state, and the USD $10 *combined* paid experiment ceiling. Choose one bounded, measurable task; specify the acceptance test and protected-data stop conditions. Do the permitted work now.
2. **Codex / Coding executor — check actual availability on every turn:** if a callable Codex executor is genuinely available with an authorized repository and cost/scope, give it a precise code-review/implementation brief with target branch, file paths, acceptance tests, prohibitions, and required commit/PR/test evidence; inspect its response. If not available, report `NOT CONNECTED / NOT INVOKED`, create the task brief for a later valid handoff, and use ChatGPT+GitHub editing where appropriate. A GitHub workflow or ChatGPT-written code is **not** Codex.
3. **Specialist agents — assess all eight functional roles but engage only useful ones:** assign explicit bounded tasks to Data/Provenance, Fundamentals, Model Research, Statistics, Audit, Devil's Advocate, Execution/Reporting as warranted. Execute an *actual* agent tool/job only after confirming connection, permissions, exact scope, costs and a reliable stop. Record agent name/ID, invocation/job ID, evidence and outcome. The repository's `Agent Fleet Pilot (dry run)` validates task planning and **is not a live specialist-agent execution**; merely drafting role-based analysis by ChatGPT is `ChatGPT analysis`, not an independent agent. When there is no callable agent, mark `NOT AVAILABLE / NOT INVOKED` and keep the exact task queued, not fabricated as completed.
4. **GitHub / Evidence and delivery — always inspect, write when permitted:** read current branch/head, source, checks, PR and issues. Record a concrete commit, artifact, review or issue/PR update for the one selected action, check the resulting CI/logs, and give exact URLs. A job that was queued/cancelled is not a PASS; a green software workflow is not price-alpha validation. Do not dispatch a manual or paid workflow merely to satisfy the four-channel checklist.
5. **After-action four-actor ledger, mandatory in every report:** show a short status line **for each** of `ChatGPT`, `Codex`, `Agents (by role)`, and `GitHub/CI` with `EXECUTED / BLOCKED / NOT INVOKED / PENDING`, the actual work done, evidence ID/link or `none`, and the reason when blocked. Distinguish tool-executed work from assigned instructions.
6. **Next owner-by-owner orders:** give a specific next instruction and measurable acceptance criterion for **ChatGPT, Codex, relevant agent roles, and GitHub**. State the execution order and dependency; a future instruction is **not** an already dispatched background job. If a role cannot execute, identify the missing executor/permission rather than promising autonomous work.
7. **Safety and spending:** respect the frozen study, locked OOS, independent witnessing, no trades, and the combined USD $10 paid-agent/API/GPU cap; if actual cumulative spend or provider cutoff cannot be verified, initiate **no new paid execution**. Do not force all agents or Codex to run simply to fill the report. Do not claim 24/7 background coordination without an actual scheduler.

**Required compact reporting layout:**
- Current Phase/Stage/E-step and one immediate measurable objective.
- **Actor ledger:** ChatGPT | Codex | named Agents | GitHub/CI, each with real status, evidence and result.
- Scientific interpretation / independent-custody gate / protected-data status.
- Verified paid spend in this turn, cumulative known-vs-unknown, USD $10 ceiling.
- **Next dispatch order:** numbered per-actor assignments, dependency and PASS/FAIL acceptance test. No user-written technical prompt required.

### Choose the right command, not the most exciting command

- **Default:** founder sends `قله: ادامه`; the assistant chooses E1/E2/E3/E4 based on evidence and prerequisites. It must make meaningful progress in the current turn where access permits.
- **Blocked E2?** Record exact source/provenance blockers and work on next *permissible exploratory* readiness task—not fake first-seen receipts, protected OOS, new paid loops or empty waiting promises.
- **E3 / E4 / E5:** These are **not automatically enabled** simply by typing their code; the assistant first verifies readiness gates and declines only the invalid operation while completing the available preparation.
- **Phase change:** The assistant must not mark Stage 7 reached because code tests passed, three directions happened to be correct, or a user requested a later stage.
- **Advanced horizons:** 6mo/1y/multi-year remain research/descriptive; official 13-horizon charter is retained.

## C. Mandatory response schema after execution

Every substantial project response must include:

1. **Where we are:** Phase/6, Stage/10, E1-E6 and the exact currently selected task.
2. **Done in this turn:** specific source/branch/file/PR/issue/workflow, plus who *actually* ran it (ChatGPT, coding tool, real AI agent, or CI).
3. **Evidence:** tests with PASS/FAIL/PENDING; source hashes, date, and relevant actual metrics. Separate engineering readiness from predictive power.
4. **Budget:** USD $10 **combined experimental paid-call/GPU ceiling**, with actual verified expense when accessible; unknown spend explicitly unknown. Not $10 per run. Do not spend when hard cap/authorized provider is not confirmed.
5. **Risk and scientific state:** untouched held-out, no replay-to-Fresh-OOS relabeling, no protected history modifications, no trading/model auto-promotion.
6. **One next action:** the next admissible command or blocked dependency. Do not quietly switch lanes.

**Example quick status**

> 📍 فاز ۵ از ۶، مرحله علمی ۶ از ۱۰ — E2
> 
> ✅ انجام شد: [real concrete code or data audit and evidence]
> 
> 🧪 آزمون: PASS / FAIL / PENDING
> 
> 📊 دقت اثبات‌شده: NO-GO unless independent evidence proves otherwise
>
> 💰 هزینه تأییدشده در این اقدام: [verified amount, otherwise unknown/not billed by this action]
> 
> ➡️ گام بعدی: [one task and one link]

## D. Safeguards and honest limitations

- Never expose private keys, API tokens, proprietary founder market rules, PII or independent locked held-out data in PRs/prompts.
- Never fabricate a missing historical candle, first-seen receipt, release vintage, trained model, agent call or CI PASS.
- Never erase, backdate, replace or quietly retune the protected 30-day BTC4h study, its issued/scored ledgers or frozen protocol.
- Never auto-trade, auto-promote a model, relax significance gates, or trigger unbounded chargeable API/GPU loops.
- Prefer documented bounded engineering work over numerous empty analyses; after any bounded bug investigation, revisit both the E1/E2 parallel paths and main 13-horizon mission.
- GitHub is persistent, **ChatGPT chat control is not an always-on scheduler**. Each sent command starts a new attempt in that turn. If an external user approval, credential, workspace selection or billing verification is required, say so and complete the safest useful subset instead.
- Do not claim available Codex, external AI subagent, plugin or GPU execution unless the actual tool action happened.
- Recheck status before interpreting dates or progress: this document is an operator interface; GitHub artifacts and independently audited evidence supply the facts.
