# BTC/USD 4-hour classical challenger tournament — isolated research draft

Status: **OFFLINE / RETROSPECTIVE / NO_RUN_ON_LOCKED_OOS / NO_PROMOTION**.
Prepared 2026-11-16. No live scheduler, no external API, no trades, no paid compute,
no new secrets, and no change to the frozen 180-slot BTC4h study or the rolling publisher.

## Question and controlled alternatives

A fixed comparison of five distinct model families on exactly the same 4h
origin/target observations and the same three features:

1. Ridge with scaling (regularization 100)
2. Elastic Net with scaling (alpha 0.0001, L1 ratio 0.25)
3. Random Forest (48 trees, depth 4, leaf minimum 5)
4. Extra Trees (48 trees, depth 4, leaf minimum 5)
5. Histogram Gradient Boosting (48 iterations, learning rate 0.05,
   at most seven leaves, leaf minimum 10)

Persistence (zero predicted log return) is always the sixth comparator.
All hyperparameters, random seeds and resource ceilings are frozen in code
**before** any research outcome evaluation. No automatic tuning or winner.
These configurations are *not* the existing live Ridge coefficients.

Features: 4-hour log momentum, BTC volume surprise, and their raw product.
Any claim that these features were actually available at the supplied
historical timestamp requires **external evidence**; a self-written timestamp
or a GitHub commit alone is insufficient.

## Input and temporal integrity

A local, manually supplied JSONL file, one row per chronological 4-hour origin,
with exactly the fields required in the script. Every row must include:
origin UTC; hypothetical or actual issued UTC (S+10m to before S+15m);
the features' first-available UTC; target five-minute-bar close (S+4h15m);
target first-observed UTC (not before bar close); origin reference price;
observed target price; and the exact three numeric features.

No request is made to Coinbase or any other provider. **No historical row
is a bona fide prospective forecast or independently verified as-of event.**
The input may contain past outcomes for retrospective analysis only.
No model issue receipt is created.

Each evaluation origin is fitted only on prior training origins whose
target was already observed before the evaluation origin's *issue* clock.
This excludes overlapping and immature labels; it does not solve
self-reported source-vintage uncertainty. Fail closed on duplicates,
out-of-order origins, mismatched target clock, future feature observations,
nan/inf, altered field schemas and fabricated four-hour horizons.

Bounded resource plan: at most 512 supplied origins, 30 fully mature training
examples before the first eligible evaluation, maximum 24 **earliest**
subsequent eligible evaluation origins, five fresh fits each, single-threaded
trees. Gaps between the first and last supplied origin are counted,
not presented as observed misses in a complete official schedule.
Evaluation cap is for feasibility and is not a statistically powered trial.

## Metrics and decision gate

Calculate per-model mean absolute *log-price* error, paired mean improvement
versus Persistence, conditional nonflat direction accuracy, eligible direction
count, and unconditional correct-over-all-evaluated fraction; a flat direction
does not silently become up. Keep the denominator and missing origins visible.
All numbers on user-provided historical rows are **descriptive only**.

**Hard stop**: always report NO_MODEL_WINNER_AUTHORIZED. No model can be merged
into live BTC4h, selected from locked OOS, or promoted based on a positive
retrospective number or a green test. Real next step requires independent
source availability and publication witnesses, a prospective preregistration
with overlap-aware uncertainty, adequate matured outcomes, and a comparison
on the identical forward issuance calendar. Do not weaken Stage-6 A1–A6
or the 0/24 scientific NO-GO to advance this branch.

## How to run locally, only with explicitly permitted offline development data

Install the optional scikit-learn dependency in an isolated user-managed
environment (not installed by this code). Then run:

    python -m scripts.btc4h_challenger_tournament --input <local-development-rows.jsonl>

The program prints a descriptive JSON report to stdout. It does not modify
the input, post a result, train the live model, or create a forecast ledger.

Unit tests:

    python -m unittest tests.test_btc4h_challenger_tournament -v

No actual Bitcoin dataset or leaderboard was generated by this PR.
